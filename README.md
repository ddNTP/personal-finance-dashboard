# 资金透视：个人财务深度分析

[打开在线分析页面](https://ddntp.github.io/personal-finance-dashboard/)

以人员为第一维度，回答“钱是谁转来的、哪些是收入、消费为何变化、与谁有资金往来”。真实读取本地微信 Excel、支付宝 CSV、招商银行 PDF，生成独立于原始文件的可分享聚合网页。

## 已实现

- **按人查看**：罗文培、胡国凤独立切换，各人的渠道卡片并列；银行与支付平台金额不机械相加。
- **时间联动**：年度快捷范围、自定义日期、月/季/年趋势；点击图表期间联动其余分析，视图链接保留人员、日期和账本。
- **收入追踪**：账单毛流入分解为可识别收入、往来、退款、本金调拨等。展开类型看到具体付款方、金额、笔数和分类依据。
- **消费复盘**：类别结构、上期/去年同期比较、变化贡献、日均/单笔、小额高频、对象集中度、大额消费日与周期候选。
- **往来分析**：搜索全部对象、分页、不同排序、收入/支出/净额；点击查看同范围的按日聚合依据与退款冲减。
- **报告**：导出当前期间报表、对象汇总、下钻依据 CSV；打印报告可通过浏览器存为 PDF。
- **质量核对**：源文件行数、退款关联、关闭订单、待确认项、银行余额连续校验。

## 复跑

要求 Python 3.9+、Node.js 18+（前端测试用）。原始账单放在人员子目录内，所有原始 Excel/CSV/PDF/ZIP 默认忽略。

```bash
python3 -m pip install -r requirements.txt
python3 scripts/build_insights.py
python3 -m http.server 8770 --bind 127.0.0.1 --directory site
```

打开 http://127.0.0.1:8770/。`--input-dir` 指定账单目录，`--output` 指定 JSON 路径。旧命令 `python3 scripts/analyze.py` 仍可使用，现统一调用新版生成器。

```bash
python3 -m unittest discover -s tests -v
node tests/test_engine.cjs
# 本地原始账单的集成验收；只解析一次 PDF
FINANCE_REAL_DATA=1 python3 -m unittest discover -s tests -v
python3 scripts/verify_data.py
```

推送 `master` 后 GitHub Actions 先执行合成数据回归和静态数据检查，再发布 `site/`。CI 不持有原始账单；更新真实数据需在本机重跑后提交脱敏聚合结果。

## 数据口径

金额以人民币分存储和计算，展示时换成元。

| 项目 | 规则 |
|---|---|
| 账单流入/流出 | 原始收支方向，剔除明确关闭、未支付或失败的记录 |
| 可识别收入 | 明确工资、利息、收益、奖励；不包含不明用途的往来 |
| 代发款项 | 单位代发，具体用途待确认；不直接当工资 |
| 理财/公积金/本人调拨 | 存量资金流动，不能整笔认定为新收入或投资收益 |
| 微信退款 | 原支出按状态冲减；独立退款入账不再重复冲减 |
| 支付宝退款 | 先按精确订单，再用对象+原描述唯一关联；累计不超原支出；不明或原单不计消费的退款不直接抵扣消费 |
| 银行退款 | 单列入账；未建立订单关联前不推定消费净额 |
| 多次导入 | 同来源、人员、订单的付款保留最新读取快照；退款事件按发生时间/金额区分；无订单号不武断删除 |
| 同期比较 | 当期、基期都需在已有记录覆盖范围内，否则提示不可比；零基数不给无限增长率 |
| 周期候选 | 同对象至少 3 个月、每月不超 2 笔、月金额变异系数 ≤20%；不是已确认订阅 |
| 大额候选 | 各日/对象聚合组最大单笔第 95 百分位与 1,000 元取较大值 |

## 已知边界

- **尚未跨渠道逐笔去重**。微信/支付宝与银行可能记录同一笔快捷支付，因此按账本核对，不能拿各渠道相加当总收入或家庭储蓄率。
- 原始账单不是全部资产和负债的快照，**不推算净资产**。往来用途和部分消费分类仍需人工确认。
- 同名不代表同一人；对象按原始名称与来源分组，姓名内号码已隐藏。银行列坐标解析对应本项目提供的招行版式，其他银行或扫描 PDF 需新增适配器。
- 分享页是静态公开汇总；任何持有链接者能查看发布数据。它不提供登录管理、密码、到期或逐链接撤销，不能据此称完整财务管理平台已完成。
- 2026 年记录不完整；银行截至 10 月 31 日，支付平台截至 11 月 3 日。覆盖标签是实际记录边界，不代表所有现实收支都已导入。

## 工程结构

- `scripts/cmb.py`：PDF 列坐标、付款方、逐笔余额校验。
- `scripts/analyze.py`：原始格式读取、付款/退款事件去重；保留历史接口供回归。
- `scripts/insights.py`：资金性质、退款关联、脱敏按日聚合。
- `scripts/build_insights.py`：一次性生成 `site/data/analytics.json`。
- `scripts/verify_data.py`：发布数据守恒和敏感字段门禁。
- `site/engine.js`：前端统一筛选、汇总、同比、候选检测与导出。
- `site/app.js`：纯前端交互、图表与下钻。

原始账单、PDF 提取缓存和本地校验中间文件都不会进入版本库。
