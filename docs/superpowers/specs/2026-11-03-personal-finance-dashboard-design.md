# 个人收支分析仪表盘设计

## 意图

把本地两个账户的微信支付、支付宝和招商银行流水转换为一个可以直接打开和分享的静态网页，用于观察 2024 年至 2026 年 11 月 3 日的收入、支出、退款、转账和消费类别变化。分析必须可重复运行，网页不依赖服务端账号，也不上传原始账单明细。

## 目标

- 读取指定目录下两个账户目录中的微信支付 Excel、支付宝 GB18030 CSV 和招商银行 PDF，自动识别表头并合并多年度文件。
- 保留收支方向、退款、转账和中性交易的原始口径，并输出月度、年度和类别聚合结果。
- 在网页中呈现合计、罗文培/胡国凤对比、月度趋势、消费类别、收入来源、支付渠道、年度对比和可行动洞察。
- 让其他人通过公开链接访问网页；源代码和生成步骤可在本地复跑。
- 只提交分析脚本、聚合 JSON、静态网页和说明文档，不提交任何 Excel、CSV、PDF 或 ZIP 原始账单。

## 非目标

- 网页允许发布账户显示名和转账对象聚合名，以支持按账户、按对象拆分；不发布商品描述、交易单号、商户单号、原始备注或银行卡尾号。
- 不把微信账单自动扩展成税务、投资或信用评估结论。
- 不依赖数据库、登录系统或持续运行的后端服务。

## 隐私与发布边界

原始文件仅从本地输入目录读取，`.gitignore` 会排除所有 Excel、CSV、PDF 和 ZIP 文件。发布的 `summary.json` 只包含按月份、年份、消费类别、收入来源、支付渠道类型和星期几聚合的数据。网页显示“罗文培 / 胡国凤”账户名和转账对象聚合名；支付渠道把具体银行卡统一成“银行卡”，不保留卡号尾号。

## 数据口径

1. 微信和支付宝的 `收入`、`支出`、`/` 或 `不计收支` 分别映射为收入、支出和中性交易；招商银行按交易金额正负映射收入和支出。
2. 收支总览使用账单金额原值，保证账单现金流可复核：总净现金流 = 收入 - 支出。
3. 消费分析只统计支出方向中非转账、非红包、非投资理财的交易。退款状态会从消费金额中扣除：全额退款扣除整笔金额，部分退款按状态中的退款金额扣除；支付宝标成“不计收支”的退款作为负向消费调整。
4. 收入来源会将退款单独列为“退款”，其余收入按交易类型归并为转账收入、二维码收款、红包等；中性交易不进入收入或支出。
5. 类别识别使用公开、可读的关键词规则，无法匹配的消费归入“其他消费”。规则写在 `scripts/analyze.py`，便于复核和调整。
6. 支付平台合计只包含微信和支付宝。招商银行流水单独展示，不纳入支付平台合计，以避免银行快捷支付与支付平台账单重复统计。

## 页面结构

- 顶部：数据覆盖时间、记录数和隐私提示。
- 来源/账户切换：支付平台合计、罗文培、胡国凤、微信支付、支付宝、招商银行。
- 指标卡：总收入、总支出、净现金流、有效消费、退款金额。
- 月度趋势：收入、支出、有效消费和净现金流的 SVG 折线/面积图。
- 消费结构：类别金额横向条形图、金额占比和笔数。
- 收入来源与支付渠道：聚合条形图。
- 往来对象：按当前账户拆分转账对象，支持全部年度/单年度切换，显示收入、支出、净流入和笔数。
- 年度对比：年度收入、支出、有效消费、净现金流和消费笔数。
- 洞察：由聚合指标生成的规则化文字，说明最高消费月份、主要类别和收入/支出变化。
- 口径说明：数据来源、退款处理、隐私边界和复跑命令。

## 技术选择

- Python 3 + pandas/openpyxl/pdfplumber：解析 Excel、CSV、PDF 和生成 `site/data/summary.json`。
- 原生 HTML/CSS/JavaScript + SVG：不引入前端构建工具和外部 CDN，保证 GitHub Pages 可直接访问。
- GitHub Actions Pages：`master` 分支推送后自动发布 `site/`，网页地址为 `https://ddntp.github.io/personal-finance-dashboard/`。

## 验收标准

- 脚本能从本地六份微信账单、三份支付宝账单和一份招商银行 PDF 生成 JSON；支付平台 12,427 条、银行流水 7,086 条，日期范围和质量统计可复核。
- JSON 不含交易单号、商户单号、商品明细、微信昵称和银行卡尾号；账户名和转账对象仅以聚合标签展示。
- 本地静态服务器能返回页面和 JSON，浏览器加载后 KPI 与图表有数据。
- GitHub 仓库默认分支为 `master`，Pages 部署成功，公开链接返回 HTTP 200。
